# 大富翁成熟界面完整插件化迁移设计

## 1. 背景

当前 `com.lanchat.monopoly` 插件只迁入了简化房间页、基础棋盘和部分规则。界面与 LanChat 0.7.2 之前的成熟大富翁差距明显，部分按钮在不满足操作条件时没有禁用说明或错误反馈，用户会认为按钮是静态占位。

本次从大富翁开始，将迁移前已经验收过的平面和伪 3D 界面、完整规则、动画、弹窗与交互整体迁入官方插件。主程序继续只提供插件框架和标准 API，不重新内置游戏实现，也不保留旧游戏兼容入口。

## 2. 目标

- 视觉和交互以迁移前成熟版本为基线，而非继续扩展当前简化页面。
- 创建、加入、准备、开始、投骰、购买、放弃、道具、聊天、邀请、结算、再来一局和退出均连接真实状态。
- 平面与 3D 使用同一个房间和同一份游戏状态，可随时切换。
- 游戏代码、资源和状态机全部位于 `lanchat-official-plugins` 仓库。
- 插件仅通过 LanChat 标准 API 使用房间、聊天、排行榜、主题和通知能力。
- 对不可执行的操作明确禁用并解释原因，不允许静默无反馈。
- 多人对局使用房主权威提交、单调版本、快照和增量事件恢复，不能依赖各客户端自行生成的事件序号。

## 3. 非目标

- 不把旧大富翁重新放回主程序。
- 不保留 `LANCHAT_GAME_INVITE:` 等旧协议或旧入口。
- 不在本阶段同时重做其他四个游戏的成熟界面。
- 不为大富翁引入独立服务端、账号体系或云存档。
- 不允许对局开始后新增玩家；中途观战不在本阶段实现。

## 4. 技术方案

### 4.1 插件应用结构

将大富翁插件从原生 DOM 脚本升级为独立 Vue 3 + TypeScript 应用。建议目录如下：

```text
plugins/com.lanchat.monopoly/
  public/
    assets/monopoly/...
  src/
    App.vue
    main.ts
    styles/
      monopoly.css
      monopoly-3d.css
    components/
      MonopolyBoardFlat.vue
      MonopolyBoard3D.vue
      MonopolyPlayerCards.vue
      MonopolyGameCenter.vue
      MonopolyEventLog.vue
      MonopolyRoomChat.vue
      MonopolyAnnouncement.vue
      MonopolyRulesDialog.vue
      MonopolyTargetDialog.vue
      MonopolySettlement.vue
    domain/
      monopoly.ts
      monopoly-room.ts
      presentation.ts
    host/
      lanchat-api.ts
      room-adapter.ts
      theme-adapter.ts
```

`App.vue` 只编排页面和对局状态，各模块独立负责一块界面。旧版 `MonopolyBoard3D.vue`、`MonopolyRoomChat.vue`、规则引擎和房间状态机作为迁移基线，清理其中对主程序 Pinia、Naive UI 全局状态及旧内置游戏入口的直接依赖。

### 4.2 宿主 API 边界

插件使用以下标准 API：

| 能力 | API | 用途 |
| --- | --- | --- |
| 房间目录 | `rooms.list` | 展示可加入的大富翁房间 |
| 创建房间 | `rooms.create` | 创建大厅并登记房主 |
| 加入/离开 | `rooms.join`、`rooms.leave` | 维护成员列表 |
| 对局同步 | `rooms.sendIntent`、`rooms.commit`、`events.onAuthoritativeRoomEvent` | 房主裁决并广播权威提交；旧 `events.onRoomEvent` 只承载兼容事件 |
| 邀请 | `rooms.invite` | 打开宿主收件人选择器并发送邀请卡片 |
| 排行榜 | `leaderboard.submit/list` | 房主按唯一终局提交结果并展示排行榜 |
| 主题 | `theme.current`、`events.onThemeChanged` | 同步软件主题色 |
| 提示 | `ui.notify` | 展示无法操作和同步失败原因 |

主程序不解析、不建模、不修改、不渲染大富翁状态，也不渲染任何大富翁组件；宿主只按通用房间协议持久化插件提供的不透明 checkpoint 和 commit payload，并统一限制载荷大小、协议版本、校验和、单房间容量与磁盘配额。

为保证所有游戏插件都能实现可靠多人同步，在 SDK 和宿主中补充下列通用、不透明的房间能力：

| 通用能力 | API | 宿主责任 |
| --- | --- | --- |
| 提交玩家意图 | `rooms.sendIntent` | 绑定传输层发送者身份，只投递给房主插件实例 |
| 权威提交 | `rooms.commit` | 仅允许房主提交，校验 `baseRevision` 并分配单调 `revision` |
| 发布检查点 | `rooms.publishCheckpoint` | 仅允许房主保存业务不透明的完整状态、协议版本、随机状态和哈希 |
| 恢复房间 | `rooms.recover` | 返回最新检查点和其后的权威提交 |
| 设置准入 | `rooms.setAdmission` | 房主在 `lobby/closed` 间切换，宿主原子校验加入 |
| 查询邀请 | `rooms.resolveInvite` | 使用宿主签发的 `inviteId + token` 向当前房主确认可加入状态 |
| 成员在线状态 | `events.onRoomPresenceChanged` | 按房间发布成员上线、离线和恢复事件 |

已有 `rooms.send` 保持现有插件兼容语义；大富翁迁移后使用新的权威协议。新增能力属于通用插件框架，参数和存储均不能出现 Monopoly 业务字段。

大富翁插件清单必须声明房间读写、排行榜读写、主题读取、通知和 `devices.read`。初次加载与 presence 事件后的资料刷新均调用 `devices.list`，用房间成员 ID 合并昵称、头像与在线状态。

### 4.3 房主权威状态同步

- 房间成员、准入状态和房间生命周期由宿主管理；插件内部保留完整游戏状态机。
- 普通玩家操作先以意图发送给房主。意图包含 `roomId`、`commandId`、`baseRevision`、协议版本和业务负载；宿主以传输层身份覆盖发送者，拒绝非成员或伪造身份。
- 房主插件校验当前玩家、回合阶段、卡牌、目标和权限，生成包含全部确定结果的权威提交。
- 宿主只接受房主的提交，原子校验 `baseRevision`，分配连续 `revision`，持久化后广播。提交包含 `commandId`、`baseRevision`、`revision`、业务事件和 `stateHash`。
- 客户端只应用权威提交。重复提交按 `commandId` 去重；高于下一版本的提交进入缓存并触发恢复，低于当前版本的提交忽略。
- 发现版本缺口或状态哈希不一致时，客户端调用 `rooms.recover`，先加载最新检查点，再按版本应用增量提交。
- 宿主事件存储设置通用容量和保留策略；创建新检查点后可以清理已被覆盖的旧提交。
- 房主所在宿主使用通用 SQLite 表在同一事务中持久化房间元数据、准入状态、当前 revision、检查点和增量提交；应用重启后先从本机数据库恢复房主房间，再恢复局域网广播。

### 4.4 随机与时间一致性

- 房主为每次状态转移生成所需的全部随机结果，包括骰子、座位顺序、建筑款式、抽卡、目标选择、随机事件、神明刷新和机器人决策。
- 权威提交携带最终随机结果，客户端 reducer 不自行消费随机数。
- 规则 reducer 禁止直接调用 `Math.random()` 和 `Date.now()`；时间、随机结果和超时动作全部作为显式输入。
- `stateHash` 使用稳定序列化后的完整业务状态计算，同一权威版本在所有客户端必须相同。
- SDK 统一使用 `canonical-json-v1`：普通对象键按 JavaScript UTF-16 code unit 升序、数组保序、仅接受标准 JSON 值，使用 UTF-8 编码后计算 SHA-256 小写十六进制；非法值、非有限数字、稀疏数组、循环和非普通对象必须拒绝。
- `stateHash` 覆盖完整业务状态，`terminal.resultHash` 覆盖终局 result，检查点 `checksum` 覆盖 `{roomId,revision,protocolVersion,payload,stateHash}`。

### 4.5 检查点与进行中恢复

- 房主在开局、每个完整回合结束、重要待处理状态产生后及正常退出前发布检查点。
- 检查点包含插件协议版本、权威 `revision`、完整游戏状态、房间席位、待处理购买/选点/付款、倒计时基准、随机结果消费状态和状态哈希。
- 重连客户端先调用 `rooms.recover` 获取检查点，再应用其后的提交；恢复完成并校验哈希后才允许操作。
- `rooms.recover` 是向当前房主宿主发起的局域网请求，普通客户端重启后通过保存的房间 ID、房主设备 ID和局域网发现信息重新定位房主。请求超时为 5 秒，不可达时进入只读重试状态，不允许本地继续推进。
- 宿主只接受 revision 与当前权威 revision 相同且 hash 一致的检查点，拒绝旧检查点覆盖新状态。若所需增量已清理，房主必须返回不低于请求版本的新检查点；不存在兼容检查点时明确返回房间不可恢复并结束本地会话。
- 进行中重连是完成标准，不允许作为后续事项跳过。

### 4.6 加入、邀请和房主离线

- 房间创建时准入状态为 `lobby`；房主开始游戏前通过 `rooms.setAdmission` 原子切换为 `closed`。
- `rooms.join` 由宿主原子检查当前准入状态、房间人数、协议版本和房间版本。
- 邀请卡由宿主签发不可猜测的 `inviteId + token`，并携带房间 ID、插件 ID、生成时房间版本和 10 分钟过期时间；版本与有效期由宿主保存并校验，不信任插件回传的声明，也不把卡片里的房间副本直接写入本地目录。
- 点击邀请时只把 `inviteId + token` 交给 `rooms.resolveInvite`，由当前房主确认；对已开局、已满、已解散、已过期或协议不兼容分别给出中文提示。
- 成员资料由房间成员 ID 与 `devices.list` 合并，逐成员在线变化通过 `events.onRoomPresenceChanged` 更新；通用网络变化事件只用于触发重新查询。
- 普通玩家掉线时保留原席位 60 秒，对局暂停其待处理操作；重连后按设备 ID 认领原席位并恢复。
- 当前玩家超过 30 秒仍未恢复时，由房主提交确定性超时动作：未投骰则自动投骰；待购买则放弃；机场选点则停留机场并结束落点；尚未提交的道具目标选择取消且不消耗卡牌；待付款时按地块索引升序先逐级拆除建筑、再出售地产，足额后付款，仍不足则破产。
- 房主短暂掉线时全局暂停 60 秒并冻结所有回合、选择和付款倒计时；房主恢复后从剩余时长继续。房主主动离开或 60 秒内未恢复时结束并关闭房间，本阶段不转移房主权威。

### 4.7 排行榜权威结算

- 只有房主可以针对终局权威提交调用 `leaderboard.submit`。
- 提交必须携带终局 `revision`、终局 `commitId`、`stateHash` 和结果；参赛名单由宿主锁定的房间席位产生，不能由插件任意传入。
- 宿主验证提交者是房主、引用的是该房间最新终局提交、状态哈希一致，并以 `roomId + terminalCommitId` 建立唯一约束。
- 断线重试必须返回同一结果；更换幂等键或重复调用不能产生第二条排行榜记录。宿主只校验通用终局引用和唯一性，不解析大富翁赢家字段。

## 5. 界面设计

### 5.1 页面骨架

- 顶部：房间名称、平面/3D切换、邀请、玩法规则、排行榜、离开房间。
- 主区域：棋盘占主要空间。
- 3D 右侧：上方事件日志，下方房间聊天，两者不重叠。
- 3D 底部：左侧玩家卡片，右侧对局中心，各占 50%，高度以对局中心完整内容为准。
- 平面版恢复原有棋盘、日志、玩家信息与对局中心布局。
- 未进入房间时展示房间列表和创建入口；进入房间后切换为完整对局界面。

### 5.2 棋盘表现

- 默认显示 3D，可切换平面版本且不重置状态。
- 3D 支持 60% 至 220% 缩放、滚轮缩放、拖动、复位、俯视和斜视。
- 建筑贴合地块底座，空地使用已确认的新样式。
- 城池名贴近当前视角可见边；后侧地块名称放内侧，前侧地块名称放外侧。
- 过路费只显示数字，位于地块中间并保持最高图层。
- 地块所有权颜色位于城池名对应的边，将该边分为三段：小屋亮一段、洋房亮两段、地标亮三段。
- 地价倍率用建筑顶部的小金币 `×2`、`×3` 展示。
- 路障、财神、穷鬼、天使和恶魔使用图片资源放在建筑前方；神明被拾取后从地块消失并附身玩家。
- 玩家棋子使用对应头像生成的小人资源。

### 5.3 信息模块

- 横幅复用平面版视觉，按事件和玩家颜色显示半透明底色，固定在棋盘中心且只显示最新一条。
- 横幅头像、神明图标和文字保持单行对齐。
- 事件日志使用平面版字号与颜色，每条只显示一行，溢出省略，悬浮显示全文。
- 房间聊天使用独立组件，结构与其他模块一致，支持回车发送和新消息自动滚动。
- 玩家卡片展示头像、金币、地产、道具、准备、在线、当前回合、破产、神明和监狱状态。
- 玩家入狱后，卡片两条对角线显示锁链和锁图标。
- 对局结算时玩家卡片和对局中心继续保留，并提供再来一局和退出。

### 5.4 弹窗

- 玩家、地块和骰点选择弹窗保持紧凑，不占满屏幕。
- 可选择项在鼠标悬浮、键盘聚焦和选中时同步改变背景、边框和文字颜色。
- 地块点击层必须位于纯装饰层之上，透明横幅不得拦截点击。
- 玩法规则展示建筑、角落、随机事件、道具和神明图片。

## 6. 操作状态与反馈

| 操作 | 可用条件 | 不可用反馈 |
| --- | --- | --- |
| 创建房间 | 未进入房间 | 已在房间时隐藏创建入口 |
| 邀请 | 已进入大厅且准入状态开放 | 未进入房间或已开局时禁用并解释原因 |
| 准备/取消准备 | 大厅阶段 | 明确显示当前准备状态 |
| 开始 | 房主、人数满足且所有真人准备 | 显示缺少人数或未准备玩家 |
| 投骰 | 本人回合、未入狱且尚未投骰 | 显示当前玩家或状态原因 |
| 购买/放弃 | 存在本人待处理地产 | 无待处理地产时隐藏或禁用 |
| 道具 | 本人回合、规则允许且目标存在 | 显示入狱、已使用或无合法目标原因 |
| 添加/移除机器人 | 大厅阶段且本人为房主 | 已开局、满员或非房主时禁用 |
| 移除成员 | 大厅阶段、本人为房主且目标不是本人 | 显示权限或阶段原因 |
| 资产处置 | 本人处于待付款且持有可处置资产 | 无法覆盖欠款时显示预计差额 |
| 再来一局 | 已结算且本人为房主 | 非房主显示等待房主 |
| 聊天 | 已进入房间 | 发送失败显示宿主通知，单机状态不弹“没有可用连接” |

按钮状态由统一的展示状态函数计算，模板不散落重复条件。每个宿主 API 调用捕获错误并通过局部状态或 `ui.notify` 显示中文信息。

## 7. 迁移方法

1. 固定迁移基线：界面模板、交互和样式取主仓库提交 `e43ef51`；规则、组件和资源取主仓库提交 `d932c7b` 中仍保留的文件。若两者冲突，后续已经通过测试的规则修复优先，视觉布局以 `e43ef51` 为准。
2. 在插件中建立 Vue/TypeScript 构建入口和宿主 API 适配层。
3. 先迁移规则与房间状态，建立等价测试；随后迁移页面骨架和功能组件。
4. 逐项替换旧主程序依赖，禁止把主程序 store 或 Tauri API 直接复制进插件。
5. 完成平面版，再接入 3D 组件和资源层级，最后恢复弹窗、动画、聊天与结算。
6. 更新插件打包脚本，将构建后的静态文件和资源写入 `.lcp`。
7. 插件验收后删除主程序中的大富翁规则、组件、样式、资源、预览和专属测试命令，只保留通用插件框架能力。

### 7.1 完整迁移矩阵

| 迁移项 | 旧版能力 | 插件目标 | 必须覆盖的测试 |
| --- | --- | --- | --- |
| 房间参数 | 人数、金币、回合数、建筑风格 | 创建弹窗完整恢复 | 参数范围、默认值、非法值 |
| 大厅操作 | 准备/取消、开始、机器人、移除成员 | 所有按钮真实可用 | 房主/成员/阶段权限 |
| 回合操作 | 投骰、超时自动、监狱、额外移动 | 完整状态机 | 正常、超时、断线恢复 |
| 地产处理 | 买地、放弃、升级、收费、联排 | 平面/3D共享状态 | 价格、等级、翻倍、查封 |
| 道具 | 弃牌、选人、选地、选骰点、被动卡 | 恢复全部弹窗与选点 | 每种卡合法/非法目标 |
| 资产处置 | 拆建筑、卖地产、补付款、破产 | 恢复付款中心 | 足额、不足、破产清算 |
| 特殊格 | 起点、机场、翻倍、监狱、随机事件 | 恢复动画和提示 | 传送、重入、目标为空 |
| 神明/物品 | 刷新、拾取、附身、消失、路障 | 恢复图片与图层 | 持续回合、覆盖、清理 |
| 信息模块 | 横幅、日志、聊天、玩家卡、对局中心 | 恢复最终布局 | 单行、滚动、重叠、主题 |
